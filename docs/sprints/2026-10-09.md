## Implemented this sprint

- A local JavaScript application with a browser library, filters, metadata editing,
  conservative edition grouping, table of contents and saved reading positions.
- Durable imports with managed source copies, hash provenance, duplicate receipts,
  resumable jobs, visible failures and explicit format/extraction omissions.
- Original PDF and EPUB reading, extracted text, citation navigation, page/section
  questions, reader-context validation and bounded source access.
- SQLite FTS5 search, local model-identified embeddings, hybrid retrieval and
  exact source locators. Ask distinguishes generated answers, abstention,
  unavailable inference and cited excerpts. Paragraph quotations and source
  offsets are validated; this mechanical validation is not factual grading.
- Local OpenAI-compatible and Ollama model adapters, bounded/resumable embedding
  work, context budgets and coverage checks for multiple named sources.
- Database-backed thumbnails, embedded source metadata, preservation of legacy
  covers and opt-in, evidence-backed recovery of deficient metadata.
- Maintenance controls that prevent import/reindex/embedding writes during review.
- The earlier offline Python ingestion/search pilot, evaluation fixtures and
  read-only MCP adapter. The older LLM committee/Qdrant pipeline and Slack
  integration remain unfinished; their presence is not a delivery claim.

## Validation and limits

Fresh publication checks are recorded here when completed. Tests run on Spark in
isolated CPU containers using synthetic fixtures; no private collection is copied
into the publication checkout. The application serves JavaScript modules directly
and has no separate bundler/build script.

Historical October 5–6 receipts reported 451 catalog books and 161,429 valid
embedded chunks, cover checks, native EPUB and ranged PDF access. A supported
question completed local answer inference with linked citations in 16.33 seconds;
an unsupported question completed inference and abstained in 5.00 seconds. These
are retained observations, not fresh October 9 quality or latency measurements.
Private source pages, answers, screenshots, databases and receipts are not included
in Git. Original file counts, logical books and indexable chunks are distinct.

Broader answer quality, actual model context capacity and complete mobile/PDF
visual acceptance remain unqualified. Synthetic or mocked tests establish contracts
and regressions, not useful answers on an entire real collection.

GitHub had no configured Actions workflows, branch protection or repository
rulesets at reconciliation. No required check is bypassed, and no GitHub-hosted
workflow is introduced. Local publication evidence and final GitHub check status
must both be reported explicitly.

## Service retirement and retained data

After the source and this report are merged and verified on GitHub, the owner has
requested decommissioning of Librarian-exclusive services. Shutdown is pending at
this publication checkpoint. This section will be updated after actual shutdown.
The app/API, embedding engine, answer engine and browser proxy are in scope;
shared runtime binaries/model files and other projects are outside shutdown scope.

Preserve the complete data directory, including SQLite sidecars, managed originals,
extracted text, embeddings, covers, reading progress and metadata. Preserve source,
model files, container images and operational logs. No data deletion, database
restore or reindex is part of retirement.

For a later restart, use the retained service definitions and private deployment
configuration, verify source/model identities and data mounts, and bring up the
existing embedding and answer engines before the app, then the browser proxy.
Keep maintenance disabled until an explicit data-maintenance decision. Verify
health, source access and citations against the retained index. Do not replay an
old rollout/rollback controller or restore an older database over newer user state.
See [application configuration](../../app/README.md#run-on-spark).

## Prioritized remaining work

   unsupported requests, multiple books, page restrictions and complete worked
   examples; retain failures and separate excerpts from generated answers.
2. Qualify model tokenizer/context limits and full-library cold/warm latency on a
   declared resource profile. The proposed 16 GiB CPU-only target is unmeasured.
3. Finish desktop/mobile original-reader visual and citation-return acceptance,
   especially PDF page geometry, cancellation and view restoration.
4. Account for unresolved metadata and extraction omissions across the collection;
   qualify conversion for remaining formats and an approved OCR path when needed.
5. Review isolated PDF-layout, partial-selection and profiling experiments before
   integrating them. Do not silently substitute experimental extraction into an
   existing text/vector index.
6. If service operation resumes, establish an intentional lifecycle, health checks,
   backup/restore verification and repeatable CI. The retained embedding container
   has a health probe aimed at its image default port rather than its configured
   serving port; correct that configuration before relying on Docker health.
7. Collections, annotations, device synchronization, broader conversion/editing,
   Slack integration and Calibre parity remain future work.
