# Librarian sprint report — October 9, 2026

## Scope and source reconciliation

This release publishes the local application developed during September 30–October 6
and reconciled on October 9. GitHub previously contained the ingestion scaffold and
website/Slack pseudocode at `33b1de50d6f2605f87593237f698001f019d76fa`.
The release imports the reconciled deployment snapshot
`ab4b29296e74d6848f34ce6da59dba92aaec6bdc` as one reviewable change on that baseline.
The source snapshot identifier records local provenance; it was not previously
published on GitHub.

All 14 local working trees were inspected. The deployed snapshot already includes
the original pilot and subsequent reader, metadata and cover fixes. The older
uncommitted pilot checkout remains untouched. An independent lexical comparison
change is already present by patch equivalence. The separate PDF indentation,
partial-PDF presentation, ranked-anchor experiment and search profiling branches
are preserved locally, not represented as qualified release functionality. Current
answer-context allocation supersedes the older ranked-anchor experiment.

On October 9, all 61 application source files in the serving source mount matched
the snapshot by SHA-256. Publication changes outside that snapshot are privacy
ignore rules, documentation, and browser-driver repairs described below.
Publishing source does not redeploy the app or migrate its database.

## Implemented this sprint

- A local JavaScript application with a browser library, filters, metadata editing,
  conservative edition grouping, table of contents and saved reading positions.
- Durable imports with managed source copies, hash provenance, duplicate receipts,
  resumable jobs, visible failures and explicit format/extraction omissions.
- Original PDF and EPUB reading, extracted text, citation navigation, page/section
  questions, reader-context validation and bounded source access.
- SQLite FTS5 search, local model-identified embeddings, hybrid retrieval and
  exact source locators. Ask distinguishes generated answers, abstention,
  unavailable inference and cited excerpts. Paragraph quotations and source
  offsets are validated; this mechanical validation is not factual grading.
- Local OpenAI-compatible and Ollama model adapters, bounded/resumable embedding
  work, context budgets and coverage checks for multiple named sources.
- Database-backed thumbnails, embedded source metadata, preservation of legacy
  covers and opt-in, evidence-backed recovery of deficient metadata.
- Maintenance controls that prevent import/reindex/embedding writes during review.
- The earlier offline Python ingestion/search pilot, evaluation fixtures and
  read-only MCP adapter. The older LLM committee/Qdrant pipeline and Slack
  integration remain unfinished; their presence is not a delivery claim.

Fresh browser runs exposed three outdated test assumptions. The recovery mock now
returns structured paragraphs with exact supporting quotations; the browser smoke
explicitly selects Extracted text before comparing exact text; the excerpt test
checks the current unavailable-answer label and verifies that no generated answer
is claimed. Production application modules are unchanged from the deployed snapshot.
The original failed runs were retained, and each repaired journey subsequently
passed. An initial mountpoint error and Python child-import/cache setup issues were
also corrected in the isolated runner; they did not change application behavior.

Historical October 5–6 receipts reported 451 catalog books and 161,429 valid
embedded chunks, cover checks, native EPUB and ranged PDF access. A supported
question completed local answer inference with linked citations in 16.33 seconds;
an unsupported question completed inference and abstained in 5.00 seconds. These
are retained observations, not fresh October 9 quality or latency measurements.
Private source pages, answers, screenshots, databases and receipts are not included
in Git. Original file counts, logical books and indexable chunks are distinct.

Broader answer quality, actual model context capacity and complete mobile/PDF
visual acceptance remain unqualified. Synthetic or mocked tests establish contracts
and regressions, not useful answers on an entire real collection.

GitHub had no configured Actions workflows, branch protection or repository
rulesets at reconciliation. No required check is bypassed, and no GitHub-hosted
workflow is introduced. Local publication evidence and final GitHub check status
must both be reported explicitly.

## Service retirement and retained data

The source and initial report were merged through [PR #3](https://github.com/jhacksman/librarian/pull/3)
at [`5372d35`](https://github.com/jhacksman/librarian/commit/5372d35bb7e866cd1e7dfb1f6f35a2ae9e3eab91)
and verified on GitHub before shutdown. Librarian was then retired on October 9
at 10:52 UTC at the owner's request. There is no serving deployment after retirement.

- The browser proxy, its SSH forward and its owner process stopped. The
  Librarian-only transient startup entry was unloaded and explicitly disabled.
- The app/API container, embedding container, answer-model user unit and both
  Librarian serving controllers stopped gracefully. Their restart policies were
  already disabled; the controllers' normal cleanup removed their owned container
  instances while retaining images and data.
- App, model and proxy listeners were absent. The two Librarian GPU processes
  disappeared, releasing their reported 19,501 MiB allocation; all five held
  CPU/GPU/data ownership locks were released.
- All 943 managed source, derived and cover files retained their size, inode and
  modification time. The 5,528,301,568-byte SQLite database was retained. No database
  restore, reindex, sidecar deletion or deliberate checkpoint was performed.
- Shared model/runtime files, images, source, logs and other projects remain.
  The separate VTuber answer endpoint and shared audio/user services were outside
  shutdown scope. This retirement did not modify system-wide Docker/SSH/security.
- A final check found that an unrelated static site's controller had a hidden
  lifetime dependency on the Librarian controller and stopped itself after that
  parent exited. Its unchanged, hash-verified files were restored under the same
  transient user service, loopback endpoint and resource/security limits, with an
  independent lifetime. Its existing LAN page returned HTTP 200 with the original
  content hash. No Librarian service was restarted for this repair.
- Follow-up checks confirmed no Librarian process, model allocation, listener,
  timer or startup unit respawned. The proxy startup entry remained disabled;
  shared audio services remained active.

Preserve the complete data directory, including SQLite sidecars, managed originals,
extracted text, embeddings, covers, reading progress and metadata. Preserve source,
model files, container images and operational logs. No data deletion, database
restore or reindex is part of retirement.

For a later restart, the private retirement bundle retains full container
definitions, the final app create command, embedding create command, answer-engine
launch command, unit definition, pre-shutdown data inventory and `RESTART.md`.
It is deliberately outside Git because runtime configuration can contain secrets.

2. Recreate/start the embedding and answer services from those saved definitions,

3. Verify app health, catalog/source reads and exact citations without importing

4. Recreate the browser proxy/SSH route under a fresh owned lifecycle. Regenerate

5. Retain new startup/acceptance receipts and update this report if operation resumes.

Do not replay old rollout/rollback controllers with stale identities or deadlines,
and do not restore an older database over newer user state. See
